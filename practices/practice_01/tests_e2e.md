# E2E-проверки

| Сценарий пользователя | Предусловия | Действие | Наблюдаемый результат | Evidence |
|---|---|---|---|---|
| Валидный diff → успешный ответ | Клиент имеет корректный JSON с полем `diff` разумного размера | Отправить POST `/api/reviews` с валидным `diff` | HTTP 200 и тело `{ "comment": <строка> }` | TO BE/ADR: успешный путь сохраняется |
| Нет diff → клиентская ошибка | Клиент готовит JSON без поля `diff` | Отправить POST `/api/reviews` | Контролируемый 4xx, без трассировки стека | TO BE/ADR: валидация входа |
| Некорректный diff → клиентская ошибка | Клиент готовит JSON с `diff` неверного типа | Отправить POST `/api/reviews` | Контролируемый 4xx, без трассировки стека | TO BE/ADR: валидация входа |
| Слишком большой diff → контролируемый отказ до вызова LLM | Клиент готовит JSON с полем `diff`, размер которого превышает предусмотренный проектом порог; конкретное значение и единица измерения — Неизвестно / требует уточнения | Отправить POST `/api/reviews` с этим JSON | HTTP 4xx (слишком большой запрос) без трассировки стека; вызов LLM при этом не выполняется | Evidence: ADR — проверка размера до формирования промпта; согласуется с `tests_integration` «Валидация размера до вызова LLM»; подтверждение — отсутствие вызова LLM по тестовому double, вход — сверхпороговый diff |
| Ошибка LLM → контролируемая серверная ошибка | LLM генерирует исключение при обработке запроса | Отправить POST `/api/reviews` с валидным `diff` | Контролируемый 5xx, без трассировки стека | TO BE/ADR: обработка исключений LLM |

## Как использовали AI

- Строка в [`prompts.md`](prompts.md): P1-05
- Что проверили и исправили сами: Сформулировали E2E-сценарии клиента по TO BE; не утверждали фактические результаты; оставили неизвестные пороги неуточнёнными.
