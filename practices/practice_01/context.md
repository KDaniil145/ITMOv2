## Context Pack для первого рабочего сценария

### Факты и правила

- Доступ к отсутствующему ключу словаря через `dict[key]` в Python вызывает `KeyError`.
- В FastAPI необработанные исключения в обработчике приводят к ответу 500.
- Отсутствие ограничений на размер входа повышает риск превышения лимитов и деградации производительности.

### Формат входа и результата

- Вход: JSON-объект с полем `diff` (ожидается строка), согласно коду обработчика.
- Результат: объект `{"comment": <строка-ответ LLM>}` согласно `ReviewService.review` и `create_review`.

### Ограничения и запрещённые действия

- Использовать только разрешённые файлы (`TRAINING_PR.diff`, `problem.md`, `context.md`, `prompts.md`) и семантику Python.
- Не придумывать отсутствующие факты или результаты проверок, не менять P1-01, не добавлять новые структуры в файлы.

### Хороший пример

Подтверждённое замечание: отсутствие валидации ключа `diff` и риск `KeyError`.

- Evidence (diff):
  ```diff
  +@app.post("/api/reviews")
  +def create_review(payload: dict) -> dict[str, str]:
  +    return review_service.review(payload["diff"]) 
  ```
- Basis / Rule: В Python обращение к отсутствующему ключу словаря через `dict[key]` генерирует `KeyError`.
- Risk: Необработанное исключение приведёт к HTTP 500 вместо контролируемой ошибки клиента.
- Verification: Отправить POST `/api/reviews` с телом `{}` (без `diff`) и ожидать необработанный `KeyError` (план проверки; фактически не выполнялся).

### Плохой пример

Неподтверждённое замечание: «Сервис использует внешний LLM-провайдер и нарушает внутренние правила безопасности при передаче diffs».

- Проблема: В источниках нет факта «внешний провайдер»; также отсутствуют указания на нарушение конкретных проектных правил.
- Почему это плохо: Основано на предположении и отсутствии прямого evidence в diff или правилах для данного PR.
- Как исправить: Сформулировать риск через наблюдаемый код (например, «diff без ограничений попадает в промпт») и сослаться на конкретный evidence; статус провайдера не указывать без источников.

### Что пока неизвестно

- Требования к аутентификации/авторизации для `/api/reviews`.
- Целевая версия Python рантайма.
- Максимальный ожидаемый размер `diff` и лимиты LLM-провайдера.
- Схема детализированного ответа (кроме поля `comment`).

## Как использовали AI

- Для чего: Проведение второго запуска ревью (P1-02) по Master Prompt для выявления подтверждённых проблем в diff.
- Тип промпта: Master prompt (структурированный, с ограничениями и DoD).
- Строка в [`prompts.md`](prompts.md): P1-02.
- Что проверили и исправили сами: Сопоставление выводов с TRAINING_PR.diff, заполнение только подтверждаемых фактов, исключение неподтверждённых предположений.
