# Анализ процесса: AS IS и TO BE

## AS IS

Текущий подтверждённый поток по доступным источникам (TRAINING_PR.diff, context.md, problem.md):

- Клиент отправляет HTTP POST `/api/reviews` с JSON `payload`.
- Обработчик FastAPI `create_review(payload: dict)` извлекает `payload["diff"]` без валидации.
- Вызывается `ReviewService.review(diff)`.
- Формируется промпт: `"Review this pull request and find problems:\n{diff}"`.
- Выполняется вызов `llm.generate(prompt)` через интерфейс `LLM.generate`.
- Возвращается результат: `{"comment": answer}`.

Проблемы и ограничения AS IS (по источникам):

- Подтверждённое поведение: прямой доступ к `payload["diff"]` — риск `KeyError` и HTTP 500 при отсутствии ключа (семантика Python).
- Подтверждённое поведение: отсутствие обработки исключений при `llm.generate(...)` — риск неконтролируемых 500.
- Потенциальный риск: не ограничен размер `diff` — возможны задержки/ошибки при больших входах (требует проверки).
- Потенциальный риск: прямое включение `diff` в промпт — возможность prompt injection (требует проверки).


## TO BE

Минимальные изменения процесса, устраняющие отмеченные проблемы, без добавления лишних компонентов:

- Валидация входа до вызова `ReviewService`: проверка наличия поля `diff` и базовой корректности формата. Некорректные запросы — контролируемый 4xx.
- Ограничение/проверка размера `diff` перед формированием промпта. Слишком большой вход — контролируемый 4xx. Конкретный порог — Неизвестно / требует уточнения.
- Контролируемая обработка исключений `llm.generate`: перехват и возврат стабильного 5xx с сообщением без трассировки.
- Успешный путь остаётся прежним: `llm.generate(prompt)` и возврат `{"comment": answer}`.

```mermaid

        E2 --> F2[llm.generate(prompt) с обработкой исключений]
        F2 -- Ошибка --> X3[Возврат контролируемого 5xx]
        F2 -- Успех --> G2[{"comment": answer}]
    end
```

## Разница

| Что меняется | AS IS | TO BE | Как проверим изменение |
|---|---|---|---|
| Валидация входа (`diff`) | Прямой доступ `payload["diff"]` без проверки | Проверка наличия и формата `diff`; некорректные запросы — контролируемый 4xx | Отправить запрос без `diff` и с неверным типом; ожидать 4xx вместо 500 (план проверки) |
| Ограничение размера `diff` | Отсутствуют явные ограничения | Проверка/ограничение размера; слишком большой вход — контролируемый 4xx | Отправить очень большой `diff`; ожидать контролируемый отказ 4xx (план проверки). Порог — Неизвестно / требует уточнения |
| Обработка исключений LLM | Исключения не перехватываются, возможны 500 | Перехват исключений `llm.generate` и возврат стабильного 5xx | Смоделировать исключение в LLM-двоике; ожидать контролируемый 5xx (план проверки) |
| Успешный путь | Вызов `llm.generate` и возврат `{ "comment": answer }` | Без изменений | Инвариант: при валидном входе и без ошибок LLM ответ не меняется |

## Как использовали AI

- Для чего: Сформировать согласованные описания AS IS и TO BE на основе `context.md`, `problem.md` и `TRAINING_PR.diff`.
- Тип промпта: Инструкция на текущий запуск (P1-03) для описания процесса.
- Строка в [`prompts.md`](prompts.md): P1-03.
- Что проверили и исправили сами: Соответствие AS IS коду и контексту; отсутствие выдуманных фактов; отделение фактов от потенциальных рисков; связь TO BE с проблемами из `problem.md`.
