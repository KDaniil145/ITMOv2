ParcelBot Style Guide

Цель
- Обеспечить минимальный, понятный и поддерживаемый код в небольшом Python‑проекте.

Имена и стиль
- Используй понятные, говорящие имена функций и переменных (snake_case для функций и переменных).
- Избегай аббревиатур и сокращений без крайней необходимости.
- Имена должны отражать поведение (например, choose_belt по весу выбирает конвейер).

Минимализм и читаемость
- Пиши минимальный код без лишних абстракций и слоёв — только то, что нужно тестам и контракту.
- Следуй принципу YAGNI: не добавляй функциональность заранее.
- Предпочитай простые условные конструкции и линейный код вместо усложнения интерфейсов.

Зависимости
- Основная логика ParcelBot должна использовать только стандартную библиотеку Python.
- Для отдельного MCP-сервера допускаются необходимые внешние зависимости после согласования с пользователем.

Документация
- Поддерживай docstring'и и README в соответствии с фактическим поведением.
- Любое изменение поведения сопровождай обновлением документации.

Тесты
- Тесты проверяют публичное поведение функции, а не внутреннюю реализацию.
- Перед реализацией новой функциональности добавляй минимальный падающий тест (RED), затем минимальную реализацию (GREEN) и только после этого рефакторинг (REFACTOR).
- Не переписывай существующие тесты ради получения PASS; если тест падает — исправь реализацию или обнови контракт по договорённости.

Организация кода
- Основная логика сортировки находится в service.py, тесты — в test_service.py.
- Дополнительные компоненты (например, MCP-сервер) могут находиться в отдельных файлах внутри директории demo.

Форматирование
- Соблюдай PEP 8 там, где это не конфликтует с минимализмом проекта.

Ошибки и исключения
- Явно валидируй входные данные и поднимай подходящие исключения (например, ValueError при некорректном весе).
