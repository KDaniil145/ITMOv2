# Итоговый журнал согласования Kanban TaskFlow

Статус: **пакет Q1–Q10/R1–R6 принят обеими командами по подтверждению пользователя**. Единый нормативный документ: [kanban-api-contract.md](kanban-api-contract.md). Создание согласованных UI v2 и Backend v2 и последующая проверка их соответствия остаются отдельным этапом; реализация не начиналась.

## Основание и происхождение подтверждения

Пользователь сообщил в текущем раунде: «Обе независимые команды — UI и Backend — приняли весь пакет R1–R6 без оставшихся возражений» и передал итоги каждого R. Это источник подтверждения окончательного выбора. Полные окончательные ответы отдельных сессий Codex в доступных файлах не представлены; координатор **не утверждает, что самостоятельно прочитал их**.

Доступные первичные материалы: [UI v1](../../specs/001-kanban-ui/spec.md), [Backend v1](../../specs/002-kanban-backend/spec.md), [полный UI-ответ предыдущего раунда](ui-feedback-v1.md), [полный Backend-ответ предыдущего раунда](backend-feedback-v1.md). История анализа: [сопоставление v1](kanban-alignment.md), [предыдущий журнал Q1–Q10 и пакет R1–R6](kanban-decisions.md). Эти документы сохраняют прежние статусы и формулировки как историю; их «не согласован» не описывает новый статус принятого пакета.

Основания процесса: [AGENTS.md, 2–6](../../AGENTS.md#L2-L6), [Constitution, 16–27](../../.specify/memory/constitution.md#L16-L27), [31–41](../../.specify/memory/constitution.md#L31-L41), [59–64](../../.specify/memory/constitution.md#L59-L64). Новые требования вне опубликованного пакета и переданных итогов не вводятся.

## Подтверждённые итоги R1–R6

Следующие записи фиксируют переданные пользователем итоги; ссылки на опубликованные предложения показывают их предысторию, а не заменяют источник подтверждения.

<a id="r1"></a>
**R1 — принято.** created_at и updated_at — UTC с ровно шестью дробными цифрами. Сортировка по значению момента created_at ASC, затем id ASC. UI сохраняет серверный порядок без потери микросекундной точности, после перемещения обеспечивает фокус и видимость карточки. Предложение: [журнал, R1](kanban-decisions.md#L113).

<a id="r2"></a>
**R2 — принято.** Минимальные долговечные отметки удалённых UUID в SQLite; удаление и отметка атомарны. Старый POST удалённого ID → 409 task_id_retired. Гарантия ограничена сохранённым состоянием хранилища. UUID и исходный POST удерживаются в согласованном жизненном цикле намерения UI; после закрытия вкладки автоматического восстановления нет. Предложение: [журнал, R2](kanban-decisions.md#L115); ограничения клиента: [UI Q3](ui-feedback-v1.md#L24-L32).

<a id="r3"></a>
**R3 — принято.** Все 17 details.code Backend; верхний error.code определяет реакцию UI. Известные ошибки редактируемых полей показываются рядом с полями, остальные — общим сообщением. Пользователь подтвердил утверждение Backend конкретных приоритетов Unicode, известных запрещённых/неизвестных полей, повторённого version и сбора независимых ошибок. Для воспроизводимой записи используется порядок **опубликованного и принятого целиком пакета R3**, а не недоступная цитата из финального ответа: [журнал, R3](kanban-decisions.md#L117), [Backend Q7](backend-feedback-v1.md#L133-L170). Если отдельный финальный текст содержит отличающуюся конкретизацию, её нельзя незаметно подменить этой записью: потребуется сверка. Подтверждённого расхождения с опубликованным пакетом сейчас нет.

<a id="r4"></a>
**R4 — принято.** version 1…9007199254740991. При актуальном максимуме реальный PATCH → 409 version_exhausted, no-op допустим, DELETE допустим. UI сохраняет черновик, автоматического retry нет. Опубликованный пакет также задаёт details=[], проверку наличия и конфликта до исчерпания и отсутствие изменений при отказе: [журнал, R4](kanban-decisions.md#L119).

<a id="r5"></a>
**R5 — принято.** Числовые показатели производительности диагностические до утверждения воспроизводимой методики. Функциональные, контрактные и интеграционные проверки, сохранность SQLite, гонки, отказы и доступность UI остаются обязательными. Методика и фактические показатели не утверждались и не измерялись. Предыстория: [UI Q9](ui-feedback-v1.md#L80-L88), [Backend Q9](backend-feedback-v1.md#L218-L238), [журнал, R5](kanban-decisions.md#L121).

<a id="r6"></a>
**R6 — принято.** Исследование удобства с пятью участниками дополнительное. Если не выполнялось, его результат обозначается **«Не проводилось»**. Обязательные функциональные и интеграционные сценарии сохраняются. Предыстория: [UI Q10](ui-feedback-v1.md#L89-L102), [Backend Q10](backend-feedback-v1.md#L240-L250), [журнал, R6](kanban-decisions.md#L123).

## Стоимость и пределы принятых решений

Отметки UUID — принятое по R2 усложнение: дополнительное долговечное состояние, проверка POST, уникальность и атомарность, проверки сбоев и гонок, рост с количеством удалений. [Backend Q4](backend-feedback-v1.md#L58-L84) оценивает стоимость как умеренную и не требует новой библиотеки для самой отметки. Это качественная оценка, не измеренные байты/часы. Содержимое удалённой задачи не сохраняется; полные квитанции и истечение срока не вводятся.

17 вложенных кодов — уточнение классификации/обработчиков и контрактных проверок, а не 17 разных UI-процессов. version_exhausted — отдельный верхний код: безопасная конечная ошибка без переполнения, сброса версий или автоматического пересоздания. Проверки границы возможны подготовленным состоянием, не триллионами операций и не новым публичным диагностическим API.

Показатели UI 2 с/200 мс и Backend 95 из 100 ≤1 с не являются обязательными SLA. Методика ещё не утверждена; диагностические результаты должны содержать среду и условия. Исследование пяти участников не проводилось в этом этапе; запись результата — «Не проводилось», не «Пройдено». Никаких фактических замеров и сессий этот журнал не подтверждает.

Существенных неустранённых противоречий между доступными источниками **с учётом переданного принятия R1–R6** не обнаружено. Различия с неизменяемыми v1 перечислены выше как намеренные согласованные изменения. Недоступность полных финальных ответов — ограничение проверки происхождения и отдельной финальной детализации, не основание заявлять самостоятельное прочтение. Если будет предоставлена несовместимая финальная таблица R3, соответствующую часть потребуется сверить до признания её точным воспроизведением.

## Короткие инструкции для следующего этапа

**UI-команде.** После отдельного разрешения создайте UI v2 отдельным документом со ссылками на UI v1, этот журнал и [единый контракт](kanban-api-contract.md). Не копируйте расходящийся API в свою спецификацию. Перенесите срок/ручной ввод года, серверный порядок и фокус, жизненный цикл UUID/POST, 404/409/неизвестный исход, осознанное применение выбранных полей, version_exhausted и карту ошибок. Сохраните темы, 390/1440 px, клавиатуру, сенсор, фокус и доступность. Скорость — диагностика; пять участников — дополнительно, «Не проводилось» без фактических сессий. Покажите соответствие сценариев и критериев контракту, без реализации.

**Backend-команде.** После отдельного разрешения создайте Backend v2 отдельно от v1 со ссылками на этот журнал и тот же контракт. Исправьте историю «только title», добавьте due_date, шесть цифр timestamp, отметки UUID, предел version, version_exhausted, 17 details.code и порядок валидации. Уточните гонки только реальных изменений и no-op, подтверждение после хранения, сохранность сроков/удалений/отметок, реальные сбои и перезапуск. Не добавляйте публичный тестовый API, новые зависимости или инфраструктуру без основания. Числовые показатели — диагностика. Подготовьте трассировку требований/проверок, не код.

Затем отдельно сверить обе v2 и контракт по полям, форматам, всем методам/ошибкам/повторам, приоритетам и критериям приёмки. Только после соответствия документов возможен разрешённый отдельный цикл планирования и реализации согласно Constitution. На текущем этапе созданы только этот журнал и контракт; прежние документы и код не меняются.

## Поправка UI после R1–R6 (2026-10-30)

Владелец TaskFlow принял новое продуктовое решение: оставить Kanban-доску единственным экраном, удалить из интерфейса «Обзор», «Календарь», «Проекты» и заглушки, открывать доску сразу и после F5. Проверка README курса не выявила требования преподавателя сохранять исходную навигацию; README практики №5 отсутствует, а корневой README описывает реализацию User Story в Spec-Driven процессе без фиксации состава экранов.

Это решение **заменяет только UI v2 S1.1 и FR-001, а также относящееся к ним сохранение Dashboard/навигации** из исходной позиции. Оно не меняет Backend, API-контракт, модель Task, CRUD, SQLite, серверный порядок, темы, бренд или требования доступности. Первоначальные UI v1, Backend v1, опубликованные ответы и решения Q1–Q10/R1–R6 выше сохранены без редактирования как история согласования; данный раздел фиксирует более позднюю пользовательскую поправку.
