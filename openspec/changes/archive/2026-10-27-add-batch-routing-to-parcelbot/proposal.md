# Proposal

## Why

ParcelBot сейчас маршрутизирует одну посылку за вызов (service.choose_belt и MCP-инструмент route_parcel). В операционных сценариях часто требуется обработка партий (batch) посылок за один запрос: это снижает накладные расходы на вызовы MCP, упрощает интеграции и позволяет обрабатывать списки отправлений за один вызов. Нужна пакетная маршрутизация, сохраняя текущую совместимость одиночных операций.

## What Changes

- Добавляется новый MCP-инструмент `route_parcels`, принимающий именованный параметр `parcels` — список объектов — и возвращающий список результатов в исходном порядке и той же длины
- Для каждой посылки переиспользуется текущая бизнес-логика `service.choose_belt(weight, priority=False)`
- Ошибки отдельных элементов не прерывают обработку: каждая ошибка отражается в результате соответствующего элемента
- Пустой входной список даёт пустой список результатов
- Существующие `choose_belt` и `route_parcel` сохраняют обратную совместимость (поведение не меняется)

Единый контракт результатов (per-item):
- Успех: {"belt": "standard" | "express" | "heavy"}
- Ошибка (доменная): {"error": "текст ошибки"}
- Ровно одно из полей на элемент результата; длина и порядок результатов соответствуют входному списку.

Входной контракт:
- `parcels`: список объектов { `weight`: number (обязателен), `priority`: boolean? (необязателен, по умолчанию false) }.
- Для числового `weight` ≤ 0 ошибка на уровне элемента: {"error": "weight must be positive"}.

Ограничение FastMCP (валидация до вызова инструмента):
- Нечисловой `weight`, отсутствующий `weight` или неверный тип структуры могут быть отклонены самим FastMCP на этапе проверки аргументов, и тогда вызов инструмента завершится с `is_error=true` (не per-item). Контракт per-item ошибок применяется к доменным ошибкам после успешной валидации формы и типов входа.

## Capabilities

### New Capabilities
- `parcelbot/batch-routing`: Пакетная (batch) маршрутизация посылок через MCP-инструмент `route_parcels`

### Modified Capabilities
- (нет) — Поведение существующих возможностей не меняется, добавляется новая способность

## Impact

- Код: practices/practice_04/demo/mcp_server.py (добавление инструмента `route_parcels`; бизнес‑логика остаётся в service.choose_belt)
- Тесты: новые авто‑тесты на успешные кейсы, смешанные приоритеты, пустой список и частичные ошибки
- Внешние зависимости: без изменений (FastMCP уже используется)
